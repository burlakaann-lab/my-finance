# Правила проєкту

Особистий фінансовий трекер на Beancount 3. Для кого він і що має показувати, описано в `PERSONA.md`. Документи проєкту: `PRD.md` (що будуємо), `IMPLEMENTATION_PLAN.md` (кроки), `PROGRESS.md` (що вже зроблено і що далі). Якщо їх ще немає, вони зʼявляться на початку роботи.

Людина, з якою ти працюєш, не має досвіду розробки. Пояснюй коротко і без жаргону: що зроблено, навіщо і як це перевірити.

## Жорсткі правила
- Папка `data/` лише для читання. Нічого в ній не змінюй, не переноси, не видаляй і не пиши туди результати.
- Після кожної зміни в обліку (`main.beancount`, `transactions.beancount`, `cash.beancount`, `import.py`, `rules.csv`) запускай `uv run bean-check main.beancount`. Зміна не готова, доки перевірка не пройде без жодного повідомлення. Показуй людині результат перевірки.
- «Готово» означає, що перевірка пройшла, а не що код написано.
- Після кожного завершеного кроку онови `PROGRESS.md` і зроби коміт у git з коротким описом українською.
- У git ніколи не потрапляють `data/`, `transactions.beancount`, `cash.beancount`, `report.html` і `.env`: у справжньому проєкті там особисті фінанси. `rules.csv` комітимо.

## Інструменти
- Python-середовище вже налаштоване через uv (`pyproject.toml`). Усе запускай лише через `uv run …`: `uv run bean-check`, `uv run bean-query`, `uv run fava`, `uv run python …`. Нових пакетів без дозволу людини не встановлюй.
- Лише синтаксис Beancount 3. Збережені запити пишемо нативною директивою `query`, а не `custom "query"`.
- Fava запускаємо на порті 5050 (`-p 5050`): порт 5000 на macOS часто зайнятий AirPlay.

## Як влаштований облік
- `main.beancount` — опції, відкриття рахунків, збережені запити і рядок `include "transactions.beancount"`. Кожен рахунок, який використовується, має бути відкритий тут директивою `open`.
- `transactions.beancount` генерує `import.py` з усіх CSV у `data/` і правил з `rules.csv`. Руками цей файл не правимо: він перезаписується при кожному імпорті.
- Правила категорій живуть лише в `rules.csv` (колонки: шаблон, рахунок, фіксована). Шаблон шукаємо в описі операції без урахування регістру. Перемагає перше правило, що підійшло, тому конкретніші шаблони стоять вище (`Bolt Food` перед `Bolt`). Операція без правила йде в `Expenses:Без-Категорії`. Надходження грошей без правила для доходу йде в `Income:Інше`.
- `cash.beancount` — готівкові витрати, які додають з телефона через `app.py`. Файл дописує лише застосунок і одразу перевіряє облік. Рахунок готівки `Assets:Готівка` відкритий у `main.beancount`.
- Телефонний застосунок `app.py` (Flask, без нових пакетів) запускається `./start.sh`. Паролі й ключ лежать лише в `.env` (шаблон `.env.example`), у коді їх немає. Сервер слухає тільки `127.0.0.1`, назовні його відкриває тунель з HTTPS. Без входу застосунок не показує жодних даних.
- Нові категорії створюємо лише через `rules.csv`: додаємо правило, відкриваємо рахунок у `main.beancount`, перезапускаємо `import.py`. Категорії руками в `transactions.beancount` не правимо.
- Рядки у виписці стоять у порядку банку. Колонка залишку (Balance) рахується саме в цьому порядку, навіть коли час операцій усередині дня йде не за зростанням. Не сортуй рядки, коли працюєш із залишком.
- Якщо в `data/` кілька виписок і рядки повторюються, однаковий рядок (дата завершення, опис, сума, залишок) рахуємо один раз.
- Назви рахунків: корені англійською (`Assets`, `Liabilities`, `Equity`, `Income`, `Expenses`), нижче — українською, слова через дефіс, без апострофів.
- Фіксовані витрати позначаємо тегом `#fixed`, а не окремими рахунками.

- Користувачі: Оля і Марко, у кожного свій рахунок у банку, лише злоті (PLN), операційна валюта в `main.beancount` — PLN. Виписки: `data/statement.csv` (Оля) і `data/marko-statement.csv` (Марко, польський формат, найновіші зверху). Операції Марка мають тег `#marko`, його готівка теж. У звіті три вигляди: Оля, Марко, Разом; Оля бачить свій і спільний, Марко — свій і спільний.
- Рахунки: `Assets:Банк` (Оля), `Assets:Банк-Марко`, `Equity:Початковий-Залишок`, `Income:Зарплата`, `Income:Інше`, `Expenses:*` за категоріями з `rules.csv` (Житло, Продукти, Кафе, Доставка-Їжі, Транспорт, Підписки, Побут, Спорт, Телефон, Інтернет, Комунальні, Розваги, Без-Категорії).
- Початковий залишок: Оля 4 500 зл, Марко 2 860,40 зл на 31 липня 2026. Виписка охоплює 1 серпня – 15 жовтня 2026, жовтень неповний і в звіті має позначку «неповний».
- Фіксовані (тег `#fixed`): оренда, проїзний ZTM, Netflix, Spotify, Claude.ai, Play (мобільний оператор). Усе інше керовані.
- Заощадження за місяць = дохід мінус витрати. Норма заощаджень = заощадження ÷ дохід. Окремого ощадного рахунку немає.
- Залишок після імпорту має збігатися з колонкою Balance у виписці.
